# ShadowVPN Desktop 0.23.0 — Tauri + Go/Xray

Windows x64 VPN client. Tauri/Rust owns the desktop window, IPC and process lifecycle. A separate Go process embeds Xray-core and creates the Windows TUN interface through Wintun. The existing HTML/CSS interface and animations are preserved.

## Быстрый запуск на Windows

Нужны Go 1.27+, Node.js LTS, [Rust с MSVC toolchain](https://rustup.rs/) и компонент **Desktop development with C++** из Visual Studio Build Tools. `shadowvpn-core.exe` не хранится в Git и собирается локально, поэтому после распаковки новой версии или чистого клонирования сначала обязательно запустите сборку.

```powershell
.\build-windows.ps1
.\start-tun.cmd
```

`start-tun.cmd` перезапускает PowerShell от администратора, ждёт завершения приложения и выполняет `tauri dev`. Права администратора нужны Xray для TUN и системных маршрутов. Собранный `shadowvpn.exe` содержит Windows-манифест `requireAdministrator`, поэтому UAC запрашивается автоматически. Если `src-tauri\target\release\shadowvpn.exe` уже существует, скрипт запустит его.

Перед распаковкой новой версии или повторной сборкой закройте приложение. Если какой-либо процесс остался в фоне и держит файлы, выполните:

```powershell
.\stop-shadowvpn.cmd
```

## Сборка

Полная сборка требует Go 1.27+, Rust MSVC, Node.js LTS и Visual Studio C++ Build Tools:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-windows.ps1
```

Скрипт проверяет отсутствие запущенных процессов проекта, тестирует Go-бэкенд и JS-мост, собирает `shadowvpn-core.exe`, при необходимости устанавливает закреплённые npm-зависимости и создаёт NSIS-установщик Tauri. Результат находится в `src-tauri\target\release\bundle\nsis\`.

## Что уже работает

- Импорт HTTPS-подписки через Go: обычные и Base64 VLESS/Trojan URI, Xray JSON; TCP/RAW, WS, gRPC, XHTTP с `extra`, HTTPUpgrade; TLS и Reality.
- Кнопка-спидометр над списком измеряет TCP connect latency всех серверов параллельно; во время проверки плавно двигается только её стрелка. Рядом находится отдельное меню сортировки: по алфавиту, в исходном порядке подписки или по минимальной задержке. При выборе задержки без готовых результатов проверка запускается автоматически; «Авто» всегда остаётся первым.
- Служебные профили подписки с адресом `0.0.0.0` или `::` скрываются до передачи списка в интерфейс и не участвуют в пинге или выборе «Авто».
- Над списком расположены минималистичные категории, формируемые локально по названию хоста: «Все», «Быстрые» (`Hysteria` или отдельный маркер `WS`), `P2P` (`Torrent`), `Gemini` (`Gemini`), `WARP` (`WARP`) и `No TLS` (`No TLS`, `No-TLS` или `No_TLS`). Один профиль может входить сразу в несколько подходящих категорий; «Авто» показывается только во вкладке «Все» и сохраняет ту же компактную высоту, что и обычные хосты.
- В меню «Группы серверов» можно создать до 24 локальных групп, переименовывать и удалять их, выбирать входящие хосты и назначать одну активной для Auto. При подключении Go/Xray получает только ID выбранных профилей и строит `leastPing`/fallback исключительно внутри активной группы. «Авто без РФ» использует тот же механизм, дополнительно исключая российские хосты; при активной группе применяется пересечение группы с фильтром без РФ. После синхронизации подписки отсутствующие хосты безопасно игнорируются; пустая активная группа не открывает соединение через все серверы.
- В разделе «Маршрутизация» доступны три безопасных режима: весь трафик через VPN (по умолчанию), выбранные направления напрямую с остальным трафиком через VPN и только выбранные направления через VPN с остальным трафиком напрямую. Правила принимают домены и префиксы Xray `full:`, `keyword:`, `regexp:`, `geosite:` и `geoip:`. Для GeoData можно указать отдельные HTTPS-источники `geoip.dat` и `geosite.dat`: клиент безопасно проверяет protobuf, кеширует первую загрузку, а Xray атомарно обновляет файлы раз в сутки с автоматическим откатом при ошибке. GeoSite и GeoIP формируются как отдельные OR-правила; сопоставление выполняется внутри TUN после DNS-sniffing. Kill Switch намеренно несовместим с режимами split-routing, чтобы прямые правила не нарушали защиту от утечек.
- Клиент всегда отправляет серверу подписки `User-Agent: shadowvpn/0.23.0`, `X-Hwid` и `X-Device-Os`. HWID — стабильный SHA-256 от Windows `MachineGuid` с namespace ShadowVPN: исходный системный идентификатор не покидает компьютер. Отключить передачу через интерфейс нельзя; текущее значение отображается и копируется в настройках.
- В разделе «Приложение» можно создать системную задачу автозапуска ShadowVPN при входе в Windows и включить автоматическую проверку задержки после стартовой загрузки подписки. Во время подключения и активного туннеля правая desktop-панель показывает приглушённую контурную карту; список серверов и горизонтальная компоновка не меняются.
- Контурная карта основана на VectorAtlas (Natural Earth), распространяемом по CC BY 4.0; лицензия включена в `src/renderer/assets/world-map.LICENSE.txt`. Карта является только декоративным фоном и не показывает геолокацию пользователя или сервера.
- Интерфейс использует локально встроенный вариативный шрифт Inter с кириллицей и настроенными весами для читаемости; лицензия SIL Open Font License 1.1 находится в `src/renderer/assets/Inter.LICENSE.txt`.
- Импортируются стандартные ссылки `hysteria2://` и `hy2://`: клиент создаёт нативный Hysteria v2 outbound и QUIC transport Xray с auth, TLS SNI, ALPN и проверкой сертификата. Для самоподписанного сертификата поддерживаются `pinSHA256`/`pcs`; удалённый из Xray режим `insecure=1` без pin отклоняется.
- Метод проверки серверов выбирается в настройках: быстрый TCP connect либо настоящий HTTP HEAD/GET через отдельный outbound каждого сервера.
- Подписка может автоматически обновляться каждые 15 минут, час, 6 часов или сутки. Во время активного VPN синхронизация откладывается до отключения и не прерывает TUN.
- URI-протоколы, которые клиент пока не поддерживает (например, `ss://`), пропускаются в смешанной подписке; количество пропущенных записей показывается после синхронизации. Если поддерживаемых серверов не осталось, отображается понятная ошибка.
- Виртуальный хост «Авто» всегда находится первым. Перед подключением он измеряет узлы и использует сервер с минимальным TCP connect latency как безопасный стартовый fallback. После запуска один Xray TUN держит все разрешённые кандидаты отдельными outbound-профилями: встроенный Observatory каждые 30 секунд проверяет их настоящим HTTP-запросом, а балансировщик `leastping` направляет новые соединения через самый быстрый живой узел. При падении текущего узла TUN не пересоздаётся; новые потоки переходят на доступный fallback, а флаг и название выбранной локации обновляются в интерфейсе и логах.
- Главное окно свободно изменяется от 720×460 px. Левая колонка адаптивно расширяется вместе с окном, но ограничена 410 px; карточки серверов стали ниже и компактнее.
- Пункт «Настройки» сохраняет существующее компактное меню и открывает отдельную панель. В ней можно выбрать DNS для TUN: Cloudflare, Google, Quad9 или до четырёх собственных IPv4/IPv6-адресов; выбор проверяется независимо в Rust и Go и применяется при следующем подключении.
- Опциональная фрагментация использует нативный Xray `finalmask` и дробит только TLS ClientHello на сегменты 10–35 байт с задержкой 0–1 мс. Параметры `sockopt` и `finalmask` из подписки не импортируются.
- Опциональный Kill Switch работает через Windows Filtering Platform (WFP), а не через подмену маршрутов. Атомарная политика разрешает loopback, DHCP/NDP, трафик через интерфейс `ShadowVPN` и соединения `shadowvpn-core.exe` только с разрешёнными IP:портами текущего сервера или кандидатов Auto; остальной прямой исходящий IPv4/IPv6 блокируется. Фильтры живут в динамической сессии и удаляются Windows при отключении, закрытии или аварийном завершении core-процесса.
- Под кнопкой подключения показывается исходный внешний IPv4. Во время подключения адрес плавно шифруется, после подключения отображаются только первые два октета выходного IP сервера и таймер текущего сеанса.
- Во время активного подключения Xray считает входящий и исходящий трафик непосредственно на TUN-интерфейсе. Под IP показываются текущие скорости загрузки/отдачи и объём данных за текущий сеанс; счётчики обнуляются при каждом новом подключении.
- При активном туннеле рядом со статусом минималистично показываются флаг и название фактически выбранного сервера. Для «Авто» Go возвращает конкретный победивший профиль, не раскрывая WebView его адрес или параметры подключения.
- Флаг сервера вынесен из названия в круглый слот карточки вместо молнии. Флаги стран отображаются локальными SVG и поэтому не превращаются в двухбуквенные коды в Windows; для профилей без флага используется нейтральный глобус.
- Меню в правом верхнем углу открывает live-логи Go/Xray/TUN, позволяет копировать или очищать их и синхронизировать текущую подписку без возврата на стартовый экран.
- Диагностический журнал хранит до 1500 строк только в оперативной памяти. Серверные URI, UUID и пароли автоматически скрываются перед отправкой в WebView.
- Серверные учётные данные остаются в Go-процессе. WebView получает только название, протокол, транспорт и случайный стабильный идентификатор профиля.
- Xray TUN для IPv4/IPv6, DNS на TUN-адаптере, автоматические системные маршруты и привязка outbound к физическому интерфейсу.
- Домен VPN-сервера разрешается до изменения DNS и маршрутов. В runtime-конфигурацию передаётся доступный IP, а исходный домен сохраняется для TLS/Reality SNI и Host/authority транспортов — это устраняет DNS bootstrap loop при первом подключении.
- HTTPS-проверка через Xray после старта. При провале ядро закрывает TUN и возвращает ошибку в интерфейс.
- Закрытый JSON-lines IPC по stdin/stdout: WebView вызывает ограниченный набор Rust-команд, Rust управляет Go-процессом.
- При закрытии окна Rust закрывает stdin и ждёт завершения Go, а Go вызывает `Xray.Close()`. Xray очищает маршруты, IP и DNS своего Wintun-адаптера.
- Один экземпляр приложения, сериализация сетевых операций, Content Security Policy и плавные анимации с поддержкой `prefers-reduced-motion`.

## Текущие ограничения

Это ранняя Tauri/TUN-сборка. Реальное подключение, Auto-fallback, Observatory, IPv6, выбранные DNS и WFP Kill Switch нужно проверить на Windows. Автоматическое переключение применяется к новым соединениям: уже установленное TCP-соединение нельзя бесшовно перенести между серверами, поэтому приложение должно открыть его повторно. Динамическая WFP-сессия защищает от утечки, пока core-процесс жив, но после его аварийного завершения Windows снимает фильтры вместе с сессией. Для определения внешнего IPv4 приложение обращается по HTTPS к `api4.ipify.org`, а при недоступности — к `ipv4.icanhazip.com` или `checkip.amazonaws.com`; подключённый адрес маскируется ещё в Go-процессе до отправки в WebView. Ссылка подписки и выбранный DNS хранятся в WebView localStorage без дополнительного шифрования. Для разработки весь Tauri-процесс запускается от администратора; перед публичным релизом сетевую часть лучше вынести в отдельную привилегированную службу.
