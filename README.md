# ShadowVPN Desktop 0.10.0 — Tauri + Go/Xray

Windows x64 VPN client. Tauri/Rust owns the desktop window, IPC and process lifecycle. A separate Go process embeds Xray-core and creates the Windows TUN interface through Wintun. The existing HTML/CSS interface and animations are preserved.

## Быстрый запуск на Windows

Нужны Node.js LTS, [Rust с MSVC toolchain](https://rustup.rs/) и компонент **Desktop development with C++** из Visual Studio Build Tools. В готовом архиве Go-ядро уже лежит в `bin/shadowvpn-core.exe`. Генерируемый файл не хранится в Git, поэтому после чистого клонирования репозитория сначала запустите `build-windows.ps1`.

```powershell
npm.cmd ci
.\start-tun.cmd
```

`start-tun.cmd` перезапускает PowerShell от администратора, ждёт завершения приложения и выполняет `tauri dev`. Права администратора нужны Xray для TUN и системных маршрутов. Собранный `shadowvpn.exe` содержит Windows-манифест `requireAdministrator`, поэтому UAC запрашивается автоматически. Если `src-tauri\target\release\shadowvpn.exe` уже существует, скрипт запустит его.

Перед распаковкой новой версии или повторной сборкой закройте приложение. Если какой-либо процесс остался в фоне и держит файлы, выполните:

```powershell
.\stop-shadowvpn.cmd
```

## Сборка

Полная сборка требует Go 1.27+, Rust MSVC, Node.js LTS и Visual Studio C++ Build Tools:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-windows.ps1
```

Скрипт проверяет отсутствие запущенных процессов проекта, тестирует Go-бэкенд и JS-мост, собирает `shadowvpn-core.exe`, при необходимости устанавливает закреплённые npm-зависимости и создаёт NSIS-установщик Tauri. Результат находится в `src-tauri\target\release\bundle\nsis\`.

## Что уже работает

- Импорт HTTPS-подписки через Go: обычные и Base64 VLESS/Trojan URI, Xray JSON; TCP/RAW, WS, gRPC, XHTTP с `extra`, HTTPUpgrade; TLS и Reality.
- Кнопка над списком измеряет TCP connect latency всех серверов параллельно. Рядом находится отдельное меню сортировки: по алфавиту, в исходном порядке подписки или по минимальной задержке. При выборе задержки без готовых результатов проверка запускается автоматически; «Авто» всегда остаётся первым.
- Служебные профили подписки с адресом `0.0.0.0` или `::` скрываются до передачи списка в интерфейс и не участвуют в пинге или выборе «Авто».
- Виртуальный хост «Авто» всегда находится первым. Перед подключением он измеряет узлы и выбирает сервер с минимальным TCP connect latency. После запуска один Xray TUN держит все разрешённые кандидаты Auto отдельными outbound-профилями, а встроенный Observatory каждые 30 секунд проверяет их настоящим HTTP-запросом через соответствующий сервер. На этом этапе мониторинг не переключает активный outbound автоматически — failover добавляется следующим изолированным этапом.
- Главное окно свободно изменяется от 720×460 px. Левая колонка адаптивно расширяется вместе с окном, но ограничена 410 px; карточки серверов стали ниже и компактнее.
- Пункт «Настройки» сохраняет существующее компактное меню и открывает отдельную панель. В ней можно выбрать DNS для TUN: Cloudflare, Google, Quad9 или до четырёх собственных IPv4/IPv6-адресов; выбор проверяется независимо в Rust и Go и применяется при следующем подключении.
- Опциональная фрагментация использует нативный Xray `finalmask` и дробит только TLS ClientHello на сегменты 10–35 байт с задержкой 0–1 мс. Параметры `sockopt` и `finalmask` из подписки не импортируются.
- Опциональный Kill Switch работает через Windows Filtering Platform (WFP), а не через подмену маршрутов. Атомарная политика разрешает loopback, DHCP/NDP, трафик через интерфейс `ShadowVPN` и соединения `shadowvpn-core.exe` только с разрешёнными IP:портами текущего сервера или кандидатов Auto; остальной прямой исходящий IPv4/IPv6 блокируется. Фильтры живут в динамической сессии и удаляются Windows при отключении, закрытии или аварийном завершении core-процесса.
- Под кнопкой подключения показывается исходный внешний IPv4. Во время подключения адрес плавно шифруется, после подключения отображаются только первые два октета выходного IP сервера и таймер текущего сеанса.
- При активном туннеле рядом со статусом минималистично показываются флаг и название фактически выбранного сервера. Для «Авто» Go возвращает конкретный победивший профиль, не раскрывая WebView его адрес или параметры подключения.
- Флаг сервера вынесен из названия в круглый слот карточки вместо молнии. Флаги стран отображаются локальными SVG и поэтому не превращаются в двухбуквенные коды в Windows; для профилей без флага используется нейтральный глобус.
- Меню в правом верхнем углу открывает live-логи Go/Xray/TUN, позволяет копировать или очищать их и синхронизировать текущую подписку без возврата на стартовый экран.
- Диагностический журнал хранит до 1500 строк только в оперативной памяти. Серверные URI, UUID и пароли автоматически скрываются перед отправкой в WebView.
- Серверные учётные данные остаются в Go-процессе. WebView получает только название, протокол, транспорт и случайный стабильный идентификатор профиля.
- Xray TUN для IPv4/IPv6, DNS на TUN-адаптере, автоматические системные маршруты и привязка outbound к физическому интерфейсу.
- Домен VPN-сервера разрешается до изменения DNS и маршрутов. В runtime-конфигурацию передаётся доступный IP, а исходный домен сохраняется для TLS/Reality SNI и Host/authority транспортов — это устраняет DNS bootstrap loop при первом подключении.
- HTTPS-проверка через Xray после старта. При провале ядро закрывает TUN и возвращает ошибку в интерфейс.
- Закрытый JSON-lines IPC по stdin/stdout: WebView вызывает ограниченный набор Rust-команд, Rust управляет Go-процессом.
- При закрытии окна Rust закрывает stdin и ждёт завершения Go, а Go вызывает `Xray.Close()`. Xray очищает маршруты, IP и DNS своего Wintun-адаптера.
- Один экземпляр приложения, сериализация сетевых операций, Content Security Policy и плавные анимации с поддержкой `prefers-reduced-motion`.

## Текущие ограничения

Это первая Tauri/TUN-сборка. Реальное подключение, Observatory, IPv6, выбранные DNS и WFP Kill Switch нужно проверить на Windows. Непрерывный Shadow Auto пока наблюдает кандидатов и пишет результаты Xray в диагностический поток, но автоматическое переключение активного outbound будет добавлено на следующем этапе. Динамическая WFP-сессия защищает от утечки, пока core-процесс жив, но после его аварийного завершения Windows снимает фильтры вместе с сессией. Для определения внешнего IPv4 приложение обращается по HTTPS к `api4.ipify.org`, а при недоступности — к `ipv4.icanhazip.com` или `checkip.amazonaws.com`; подключённый адрес маскируется ещё в Go-процессе до отправки в WebView. Ссылка подписки и выбранный DNS хранятся в WebView localStorage без дополнительного шифрования. Для разработки весь Tauri-процесс запускается от администратора; перед публичным релизом сетевую часть лучше вынести в отдельную привилегированную службу.
